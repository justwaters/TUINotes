How it talks to Notes.app

There's no public API for Apple Notes, and its database is undocumented and partially encrypted, so reading it directly means guessing at a format Apple can change on any update. TUINotes uses the same door Notes.app already leaves open to itself.

  1. 1 TUINotes runs a small script through osascript

    The automation tool built into every Mac, the same one behind countless menu-bar utilities and Shortcuts.
  2. 2 Notes.app receives it as a native Apple Event

    The same channel its own AppleScript support has offered for years, and reads or writes the note.
  3. 3 The result comes back as JSON

    TUINotes turns it into the two panes you're looking at.
Notes save as plain text, with one exception: lines starting with * , - , or 1. become real bulleted, dashed, or numbered lists — matching the exact HTML Notes.app uses for each, reverse-engineered from real notes since Apple never documented it.

What it won't do

Nothing here is hidden until it breaks on you.

  • Checklists show up as plain bulleted lists. Apple's automation interface doesn't expose checklist state at all — a checklist's underlying HTML is identical to a bulleted list — so there's nothing for TUINotes to tell apart or preserve.
  • Notes with attachments open read-only. Images, scans, and drawings stay untouched — TUINotes won't save over a note it can't fully represent.
  • Bold, italics, and headings are dropped to plain text. Lists are the only formatting that survives a save.
  • Search covers one account. If you split notes across iCloud and On My Mac, only the first is indexed.

Get it running

Requires macOS with Notes.app and Go 1.24+.

$ go install github.com/justwaters/TUINotes/cmd/tuinotes@latest

Or build it from source:

$ git clone https://github.com/justwaters/TUINotes
$ cd TUINotes && go build -o tuinotes ./cmd/tuinotes

The first time TUINotes talks to Notes.app, macOS will ask your terminal for permission to send it Apple events — that's expected, not TUINotes asking for anything unusual.
